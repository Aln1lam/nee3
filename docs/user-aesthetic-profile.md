# 用户审美画像与视觉风格指南 (User Aesthetic Profile)

> **用途**：后续 AI / 人工开发的**硬性约束**。与 `docs/ui-style.md` 互补——后者是工程 Token 规范，本文是从真实迭代中提炼的**审美决策偏好**与**反模式黑名单**。  
> **产品语境**：NEEPU CTF 平台（工作台 / 知识 / 训练 / 赛事 / 公告 / 运维后台）  
> **提炼来源**：登录弹窗、公告/Wiki、赛事大厅与赛场概览、后台表格、侧栏返回按钮等多轮像素级精修与回退  
> **基准页**：`Home.vue` + 训练场侧栏模式 + 薄荷绿 Code Chip 体系

---

> **工程与 Token 规范**：本文档与 [UI Style Token Guide](./ui-style.md) 互补，共同构成项目硬性视觉约束。

## 0. 一句话总纲

**深色 Obsidian 极客 HUD + 薄荷绿微光签名 + 毛玻璃轻质感 + 248px 通底侧栏 + 三字母 Code Chip。**  
追求「工业级终端感」与「信息清爽」，拒绝「AI 机械模板味」与「塑料药丸堆砌」。

---

## 1. 视觉主基调 (Visual Theme)

### 1.1 色彩搭配（必须）

| 角色 | 偏好值 / Token | 说明 |
|------|----------------|------|
| 画布底 | `#0B0E14` / `var(--page-bg)` | 死黑空洞感要避免；用微透卡片填充舞台 |
| 卡片面 | `rgba(15~20, 21~26, 28~33, 0.6~0.85)` | Obsidian 毛玻璃，非纯黑实心块 |
| 主强调色 | `#10b981` / `#5ED9A8` / `var(--primary)` | **薄荷绿唯一主签名**；Chip/选中/CTA 统一走绿 |
| 微光边框 | `rgba(16,185,129,0.18~0.35)` 或 `rgba(94,217,168,0.18~0.2)` | 细边框 + Hover 边框提亮，而非粗霓虹管 |
| 正文 | `#e5e7eb` / `var(--text)` | 简介/阅读区提亮，禁止发灰发糊 |
| 次要文字 | `#9ca3af` / `var(--muted)` | 标签、字数、时间元信息 |
| 危险操作 | `#f87171` + `rgba(239,68,68,0.1)` 底 | 柔和暗红文字钮，禁止刺眼块状撞色 |

### 1.2 氛围关键词

**采用**：深色极客 · 终端 HUD · ret2shell · 毛玻璃 · 微发光 · 克制赛博 · 高校 CTF 信息密度  

**拒绝**：高饱和死绿全填充 · 霓虹过曝 · 紫粉渐变主题 · 奶油纸质编辑风 · 报纸排版 · 浅色 Autofill 刺眼白底 · 「黑框套黑框」套娃

### 1.3 材质与光效

- **毛玻璃**：`backdrop-filter: blur(12px~16px)` + 半透明深底  
- **Glow**：Hover / Active 用 `box-shadow: 0 0 16~24px rgba(16,185,129,0.25~0.35)` 或 **inset 内发光**；默认态少光  
- **装饰**：禁止弹窗两侧方括号 `[` `]`、假搜索、无意义占位模块

## 2. 组件与 UI 细节 (UI Detail Preferences)

### 2.1 圆角与形体

| 元素 | 规范 | 禁止 |
|------|------|------|
| 卡片 / 面板 | `8px~12px`（优先 `var(--card-radius)` ≈ 10px） | `2px` 硬直角 |
| 列表项 / Sidebar Item | **矩形微圆角 `8px`，`width: 100%`** | `border-radius: 9999px` 药丸列表 |
| 三字母 Code Chip | **保留胶囊 / pill**（`item-code` / `link-code` / `chip-cut`） | Chip 改成粉/紫；去掉代号 |
| 状态 Badge | 小胶囊或微圆角 chip（11~12px） | 大块原生 checkbox / 原生 select |

### 2.2 按钮

- **主 CTA**：薄荷绿底 `#10b981` + 深色字 `#0a0f14`，字重 600，高约 `38~48px`；Hover 微光阴影，**不要死板高饱和全填充「塑料绿」**  
- **次按钮**：暗灰微透底 + 淡边框  
- **侧栏返回**：标准结构  
  `[三字母 Code]` + `模块名`  
  例：`[WKI] 知识库`、`[CTF] 返回赛事`、`[BAK] 训练中心`（代号须与模块语义匹配，**禁止乱套 BAK/WKI**）  
- **表内操作**：文字型微光钮（编辑绿 / 删除柔红），禁止粗块撞色

### 2.3 输入框

- 高度 **42~44px**，`padding: 0 14px`  
- 背景 `rgba(255,255,255,0.03~0.05)`，边框 `rgba(255,255,255,0.1)`  
- Focus / Hover → 薄荷绿微光边框 `rgba(16,185,129,0.4)`  
- 文字 `#ffffff` / 14px  
- **必须覆盖 WebKit Autofill**，强制深底白字，禁止浏览器白底破坏暗黑主题

### 2.4 卡片与弹窗

- 登录卡：`padding: 32px 28px`，比例舒展，毛玻璃 + 薄荷绿描边 + 深阴影  
- 管理大卡：工具栏与表格同容器整合，避免「孤立矮表」  
- **禁止**：卡片套卡片、外挂悬空 H1、Hero 外再套一层黑底座（海报套娃）

### 2.5 字体与排版

- UI：无衬线系统栈 / 项目 `--font-ui`（禁止 Inter 作为主 UI 字体）  
- Mono：`JetBrains Mono` / `Fira Code` —— Flag、Code Chip、面包屑、终端字  
- 阅读正文：`14~16px`，`line-height: 1.7~1.8`，`color: #e5e7eb`  
- 元信息 / 字数：`12~13px`，`#9ca3af`  
- 侧栏标题约 16px / 600；列表项约 12~13px

### 2.6 海报与媒体

- **强制 `aspect-ratio: 16 / 9`** + `object-fit: cover`  
- 大卡片内 **上/下/右三边等距留白**（常用 `padding: 32px`）——反复迭代的核心审美点  
- Hover：轻微 `scale(1.02~1.03)` + 薄荷绿蒙层；提示用克制文案（如右下角 `ENTER ARENA ↗`），**禁止海报中央巨大胶囊按钮**  
- 无海报：统一 Cyber 微光渐变占位，禁止裸露死黑或文字 `CTF` 占位

## 3. UX 与交互习惯 (UX Preferences)

### 3.1 信息架构

1. **前台只读 / 后台 CRUD**：选手端禁止发布、编辑、删除入口；管理能力只在 `/admin/*`  
2. **一屏一事**：大厅不做详情堆砌；详情不做列表三重复  
3. **侧栏底栏规范**：返回 / 版权固定在 **最左侧 Sidebar 最底部**（`mt-auto`），不塞进 TOC / 中间卡片  
4. **顶对齐**：左侧 Sidebar 与右侧主内容卡片顶部起点平齐；禁止卡片外悬空大标题

### 3.2 导航与列表

- 偏好 **一级平铺列表**（Wiki 文章列表最终形态）；过度分类折叠易被视为噪音（可折叠树仅在「题目分类」等确有层级时使用）  
- 选中态：**Glass Glow 充盈**（淡薄荷绿底 + 1px 微光边 + 可选 inset 光）  
  **禁止**：生硬左侧 `border-left: 3px` 亮条作为唯一选中语言  
- 排序优于一排筛选 Chip：如赛事「状态权重 + 时间倒序」自动排序，去掉冗余「全部/进行中/…」按钮条

### 3.3 视口与滚动

- 带侧栏页：壳层 `100vh - nav`，**Header / Sidebar 不随滚**  
- 概览类页：倾向 **定死视口、禁止整页大滚动条**；长文在内容区内滚  
- 滚动条：细 `6px`、半透明 thumb，禁止粗糙原生粗条  
- 统计卡 / 工具栏：压缩高度，把纵向空间留给表格（一屏 10~15 行可读）

### 3.4 动效

- 克制、有目的：Hover 微浮 `translateY(-4px)`、边框提亮、海报微放大  
- 切换文章 / 赛事：路由热更、选中高亮，追求「平滑无整页闪白」  
- 禁止为动而动的装饰动画堆叠

### 3.5 验收习惯

- 改完必须 **`npm run build`**  
- 常以截图/红框做像素级验收；不对齐会要求返工直至「肉眼三边等距」  
- 风格漂移可被要求 **退回上一步**——改动应可回滚、步幅可控

## 4. 代码实现偏好 (Tech & Styling Code)

### 4.1 工程习惯

| 项 | 偏好 |
|----|------|
| 大段 UI 改写 | **Python UTF-8 脚本**写文件（避免中文乱码 / PowerShell 转义） |
| 组件 | Vue SFC；现有代码多为 Options API，不强制改写 Composition |
| 样式 | Scoped CSS + 全局 Token（`golden-ratio.css` / `neepu-matrix.css` / `collapsible-sidebar.css`） |
| 布局壳 | `layout-with-sidebar` + `sidebar-rail`（248px）+ `sidebar-collapse-trigger` |
| 类名表述 | 需求里常写 Tailwind 风格类名作规格说明；落地可转成 scoped CSS，但**视觉结果必须对标** |
| Chip | 复用全站 `item-code` / `link-code` / `sidebar-link`，禁止私造一套颜色 |

### 4.2 禁止的实现味道

- Vue scoped 里随意覆盖页面级 padding / grid 导致与 `golden-ratio.css` 打架（需时双写加固）  
- 硬编码与 Token 体系冲突的「另一套皮肤」  
- 为对齐某页而复制粘贴第三套侧栏 DOM，却不复用标准 footer / chip 结构

## 5. 人物画像与沟通偏好 (Developer Persona)

### 5.1 角色画像

- **产品 + 设计总监型开发者**：同时关心架构隔离、像素对齐与选手体验  
- **规范驱动**：反复要求对齐「训练场 / 内容管理 / ui-style / Home」既有模板  
- **迭代型决策者**：允许探索（分类树 → 平铺；BAK → WKI），定稿后要求立刻统一；错误方向会明确「退回上一步」

### 5.2 沟通与交付期望

- 指令风格：**结构化、编号、附带目标 HTML/CSS 片段**；期望原样落地而非「差不多」  
- 回复期望：**短结论 + 改了什么**；少空话；中文简体  
- 交付闭环：改代码 → build → 说明验收路径（路由）  
- 对「AI 模板感」极度敏感：干瘪两行字、中央大胶囊、药丸列表、黑洞留白都会触发重构

### 5.3 审美价值观（优先级）

1. **全站一致性** > 单页炫技  
2. **信息清晰与空间利用率** > 装饰密度  
3. **微光克制** > 霓虹堆叠  
4. **语义正确的 Code Tag** > 随便套一个三字母  
5. **可回滚的小步精修** > 一次性不可逆大改

## 6. AI 开发硬性约束清单（Checklist）

做任何 UI 改动前，默认遵守：

- [ ] 深色主题自洽；Autofill / 输入框不得出现白底  
- [ ] 主色仅为薄荷绿系；Chip 不得粉/紫  
- [ ] 列表项矩形 8px；**仅 Code Chip 用胶囊**  
- [ ] 侧栏返回在 **Sidebar 最底部**，结构为 `[CODE] 名称`，CODE 语义正确  
- [ ] 无卡片外悬空大标题；Sidebar 与主卡顶对齐  
- [ ] 海报 16:9 + 对称留白；无黑框套娃、无中央巨大 CTA 胶囊  
- [ ] 选中态 Glass Glow，不用生硬左边亮条当唯一语言  
- [ ] 前台无 CRUD 入口  
- [ ] 消除死黑大留白；优先铺满或智能排序/网格填满  
- [ ] 大改用 Python UTF-8；完成后 `npm run build`  
- [ ] 不确定时对齐：`Home.vue` / `Training.vue` / `ChallengeWorkspace` 底栏 / `ContentManagement` 工具栏

## 7. 反模式速查（Do Not）

| 反模式 | 正确替代 |
|--------|----------|
| 悬空「返回」纯文本 | Sidebar 底 `[CODE] 模块名` |
| TOC 内塞返回按钮 | 最左 Sidebar footer |
| 分类折叠过度（Wiki 全量列表） | 一级平铺 + 独立滚动 |
| `BAK` 用在知识库 | `WKI` |
| 药丸形赛事/文章列表项 | 8px 矩形 List + Glass Active |
| 左侧 3px 亮条选中 | 微透薄荷绿底 + 细边框 + inset |
| 海报中央「点击进入」大胶囊 | 纯海报 + Hover 角落提示 |
| Hero 黑底座套海报 | 海报容器透明、直接 cover |
| 整页大滚动条（概览） | 定高 + 内容区滚动 |
| 表格外再套厚重卡片套娃 | 工具栏与表同层清爽容器 |
| 前台「发布/投稿/新建」 | 仅 `/admin` |
